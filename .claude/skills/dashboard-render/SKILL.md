# Look at the render

Building is not seeing. A dashboard change was once shipped with every colour sampled correctly and
the geometry untouched — seven different corner radii against the mockup's one, no inner bevel —
because it was verified by reading a build log. `npm run build` exiting 0 says nothing about what
the page looks like.

Two things make this dashboard specifically easy to get wrong:

1. **The CSS the operator sees is compiled into the assembly.** `Vortex.Dashboard.API.csproj` has
   `<EmbeddedResource Include="Assets\*.css" />`. Writing `Assets\` changes *nothing* for a running
   `Vortex.Main` — it serves the copy embedded at its last build.
2. **Colour is the easy half.** Radii, borders, shadows and insets are what make a card read as a
   different card. Check geometry explicitly; it does not announce itself.

## 1. Iterate against the dev server, not the build

`vite.config.js` proxies `/api` and `/hotel-assets` to `http://localhost:9000` and uses `base: '/'`
in dev, so this is real HMR against the running emulator — the session cookie stays same-origin
through the proxy and SSE works.

```bash
cd Vortex.Dashboard.Web && npm run dev     # -> http://127.0.0.1:5173
```

No `dotnet build`, no restart, no emulator interruption while iterating.

## 2. Capture it

**Authenticated pages** — drive a real browser with the `chrome-devtools` or `playwright` MCP: log
in once, navigate, `take_screenshot`. Headless Edge on a protected route only ever photographs the
login page.

**Component CSS, no auth, no emulator** — the isolated harness is enough and is faster:

```bash
cp "$(ls -S Vortex.Dashboard.API/Assets/*.css | head -1)" /tmp/dash.css   # -S: biggest = main sheet
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless=new --disable-gpu \
  --hide-scrollbars --window-size=1200,700 --screenshot=/tmp/out.png "file:///tmp/harness.html"
```

A harness page with `.panel` / `.stat` / buttons / table markup covers most of it. Then `Read` the
PNG — actually read it, that is the entire point of this skill.

## 3. Compare numerically, not by eye

Sample the same edge profile in both images — a vertical cut through a card border — and diff the
hex. That is what surfaced the inner bevel: the mockup goes `#3f6c94 -> #1a3f65 (darker) -> fill`,
and a plain 1px border cannot produce that. "Looks close" is how the first attempt passed.

## 4. Before committing only

The embedded copy on :9000 is still stale until:

```bash
dotnet build Vortex.Dashboard.API
```

Then **the user restarts** — the build succeeds while the emulator runs, but never stop it yourself
(`scripts/hooks/guard-emulator.mjs` blocks it, and the running hotel is the live-verification
environment).

## Notes

- `Vortex.Dashboard.API/Assets` is gitignored and regenerated by `dotnet build`, which runs `npm ci`
  + Vite itself and errors if it would embed nothing.
- Svelte styles are component-scoped; only `src/styles.css` is global.
- Adding a page rather than restyling one? `new-dashboard-page` has the four-file capability
  checklist and the ergonomics rules (`AssetImage`, `PickerModal`, tabs).
